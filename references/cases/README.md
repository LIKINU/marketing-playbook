## 一、怎麼用（三步，別通讀）

1. **只開你客戶所屬的那 1 個行業檔**（見下方對照表）。其餘 44 個行業檔與你的案子無關。
2. 進檔後**先讀「案例清單」** —— 每條寫了「做了什麼／結果／可抄的點」，30 秒掃完。
3. 挑中 1–3 個 → **跳「深度拆解」看深度卡**（每卡五要素：是什麼／為什麼／做了什麼／怎麼做／效果）。

> ⛔ **不要把 `cases/` 當資料庫查詢。** 它的用途是「**在方案裡掛上可抄的參照**」——
> 打法組合表最後一列「可抄案例」必須寫出**具體卡號＋它的動作**，不是「參考同業做法」。

### ⚠️ 定位章節請用「**標題名**」，不要用「第幾節」

45 個行業檔的章節**組成不同**（有的 6 節、有的 8 節），所以**同一節在不同檔的序號不同**——
「本行業對接實測清單」在 A 檔是第四節、在 B 檔是第六節。**用序號找必定撲空。**

## 四、卡片格式（**2026-09-16 起的統一規範**）

每張深度卡必須有 **五個要素標題**：

```
### 3.N 品牌｜角度（年份）

**① 是什麼** —— 誰、賣什麼、什麼賽道（只講理解這個案子必需的）
**② 為什麼** —— 當時的問題／目標（不是公司困境，是**營銷上的卡點**）
**③ 做了什麼** —— 動作的**實概括**（不是「共 N 件，見④」這種指針）
**④ 怎麼做** —— **精確到每一步**：每步寫「做什麼／要點／產出」
**⑤ 效果** —— 只寫「這次動作造成的結果」＋ ⚠️ 歸因提醒
```

**卡尾建議附三個實用塊**（這是「小客戶怎麼抄」的關鍵）：
- **適配不同規模客戶** —— 大／中／小三個版本分別怎麼抄
- **常見錯誤** —— 照抄時最容易踩的 3 個坑
- **本檔關聯** —— 交叉引用的其他卡號

### ⛔ 硬規則（違反＝這張卡白做）

1. **嚴禁公司背景**：創始人、成立年份、股權、融資、營收、人事 —— 對做營銷毫無用處。
   - **例外**：`46–50` 機構／書籍類可保留「理解其方法所必需」的背景。
   - **卡標題（品牌名）必須留** —— 參考案例就是要知道「參考的是誰」。
2. **唯一允許的數字是「這次營銷動作造成的結果」**（銷量／曝光／門店／復購）；公司財報數字不算。
3. 必須寫**具體動作**（例：「用包裹卡把線下客導到企微、朋友圈按 3:2:1 發、4.8 折社群券替代全量 3.8 折補貼」），
   禁止只寫「私域運營」「品類創新」「超級符號」。
4. 每張卡要有 **「解決了什麼問題」＋「得到了什麼結果」**，且**至少 1 處可信度標記**（`【已核實】`／`【行業認知】`／`【未核實】`）。
   **`【未核實】` 不得寫進對外交付物。**
5. **查不到就寫「未披露」**，不猜不編。編造數字在商務場景會害死人。

## 五、維護

```bash
# 體檢：每卡五要素齊不齊 + 字數夠不夠（目標 ≥2500 字）
python scripts/case_upgrade.py --file 01        # 看某檔
python scripts/case_upgrade.py --list           # 列未達標

# 查「公司背景」違規（預設豁免身份欄／歸因欄；--strict 裸計數）
python scripts/case_lint.py

# 查卡片「要素順序」是否規範（①→誰做的→②→洞察→③→④→花了多少→⑤→…→局限）
python scripts/case_order.py                    # 只體檢
python scripts/case_order.py --fix --file 38    # 修復（零刪除＋硬不變式）

# 升級某檔前：一屏看完骨架（判斷是「補尾塊」還是「寫正文」）
python scripts/case_digest.py 27,28 120

# 升級某檔前：掃出五類斷句損壞（打印完整壞行，便於一次寫完修復）
python scripts/case_scan.py 27

# 輸出「未達標清單」而非進度條
python scripts/case_upgrade.py --list

# 清理違規（子句級，帶保護閘）／補結構標籤（機械、零編造）
python scripts/case_clean.py --scope identity   # 先 dry-run 看
python scripts/case_relabel.py
```

> **分兩層做**（2026-09-16 的教訓）：
> **結構層**（改名／加標籤，機械可做，一次全量）／**內容層**（補實質內容，必須逐卡寫）。
> 兩層混在一起做，要麼卡住、要麼注水。

> 新增或改名任何檔 → **必須同步三處**：`../../SKILL.md` 第 -1 步導航表、`../../AGENTS.md` §五 檔案地圖、本頁對照表。
> 改完章節或卡片後，跑 `python scripts/file_meta.py --fix` 讓檔頭「目錄／規模」自動重算。

## 六、卡片內容硬規則（`case_lint.py` 按此檢查）

1. **嚴禁公司背景**：創始人、成立年份、股權、融資、營收、人事、服務方自我介紹
   —— 對做營銷沒有用。卡裡的人是「做這個動作的人」，不是公司傳記。
2. **唯一允許的數字是「這次營銷動作造成的結果」**：銷量／曝光／門店／復購／轉化。
   **公司財報數字不算**（除非它本身就是該動作的結果口徑，且已標明來源）。

### 兩項計數例外（2026-09-17 決策 A）

| 欄位 | 為什麼例外 |
|---|---|
| `- **誰做的**：` | 這是**格式規定的身份欄**，設計上就要寫「甲方自建／創始人／成立年份」。它回答「這個案例屬於誰」，不是公司傳記。 |
| `- ⚠️ **歸因提醒**：` | 這一欄的**職能就是口徑溯源**——必須指名「某人在某場合披露」才能讓人核到源頭。去掉人名它就失去意義。 |

`case_lint.py` 預設不計這兩欄（`--max 900`，2026-09-17 實測基準 748）；
加 `--strict` 恢復裸計數（1043）。**上限是「攔新增膨脹」的趨勢預警，不是要求清理既有存量的硬門檻。**

> 已知存量：`--strict` 計數約 1023，主要來自 `⑤ 效果` 裡直接引用的上市公司營收／財報數字。
> 這是**既有狀態**，逐條清理屬格式層決策，未經確認不動。
