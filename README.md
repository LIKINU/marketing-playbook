# marketing-playbook · 使用說明

> 一句話：**你把客戶情況說清楚，它給你一份完整的營銷方案 Word 文檔。**
> 不是查資料，是生成方案。

---

## 一、用它之前要知道的一件事

**它會先問你一堆問題，問完才動手。**

這是刻意設計的。沒搞清楚客戶情況就出方案，等於算命。所以第一次使用時：

1. 它會對照 **13 項門禁清單** 逐項核對，列出你還缺哪些信息
2. 一次性把缺的問完（不會擠牙膏）
3. **產出《任務規則表》請你確認**（門禁答案＋交付結構＋紅線）
4. **你確認之前，它不會出任何方案內容**

13 項門禁：賣什麼／賣給誰／現在規模／卡在哪／預算／現有資源／時間死線／硬約束／決策人／競爭對手／過去試過什麼／怎麼算成功／**目標字數**。

> **為什麼有「目標字數」這一項**：比賽提交、招標文件、客戶模板常有字數或頁數上限。先問再寫，比寫完再砍划算。

## 一點五、八條強制協議（違反任何一條＝這次使用失敗）

| # | 協議 | 白話解釋 |
|---|---|---|
| 1 | **啟動即立規** | 問完就出一張《任務規則表》給你確認；**你之後每次糾偏＝規則表升級**，它要先複述再動手，不許當一次性修補 |
| 2 | **結構衝突「合併，不取捨」** | 你若有指定格式（比賽清單、客戶模板），它會把該寫的內容**映射進去，硬要素一件不丟**；不許為了貼合格式砍深度 |
| 3 | **交付前自檢單原樣輸出** | 說「完成」之前，必須在回覆裡逐項打出 12 項自檢單並標 ✅/❌；有 ❌ 就不許說完成 |
| 4 | **工具盤點先於路徑** | 要讀外部資料時，**先盤點已連接的連接器／API**，能用連接器就不許用爬蟲硬繞（燒額度主因）；付費生成先報價 |
| 5 | **交付形態紅線** | 對外一律**簡體 `.docx`**；**內部過程文檔（事實底稿／Agent 分工／裁決記錄）不得混進交付稿** —— 你要的是作品，不是工作過程 |
| 6 | **每輪開頭輸出《流程狀態》行** | 它每輪回覆第一行必須是：`【營銷方案 · 流程狀態】門禁 13 項：x/13（缺：…）｜ 任務規則表：…｜ 當前階段：…`。**缺了這一行，就代表它跑偏了** |
| 7 | **跨平台一致** | 不許依賴某個平台的特有能力；能力不足要降級（例如不能派多 Agent 就順序扮演），**但降級不等於跳步** |
| 8 | **卡死處理（不許把自己卡死）** | 同一項校驗**連續 2 次不過 → 停止重試**，把問題攤給你、給你 2–3 個選項選；腳本報錯或環境不可用 → **降級成 Markdown 繼續產出**；跳過一律**留痕**（明說哪幾項沒檢查）。**不許**同一錯誤重試超過 2 次、不許因校驗不過就不交付、不許靜默跳過 |

> 這八條不是口號：執行 AI 最常見的五個失敗模式（骨架式使用／跳過自檢／門禁漏項／工具慣性繞路／結構衝突做減法）都在 `references/04-失败归因总库.md` 附錄，每條協議各自堵住一個。

## 一點七、怎麼一眼看出它有沒有照做（你只需看 3 處）

| 看哪裡 | 正常 | 有問題 → 你怎麼說 |
|---|---|---|
| **回覆第一行** | 有 `【營銷方案 · 流程狀態】…` | 沒有這行 → 「**你沒輸出流程狀態**」（它必須補上並回到正確階段） |
| **動筆之前** | 先問你問題（門禁 13 項）→ 出《任務規則表》等你確認 | 直接開始寫方案 → 「**先出任務規則表**」（強制走協議 1） |
| **說交付之前** | 原樣輸出 12 項自檢單並標 ✅/❌ | 只說「已完成」→ 「**把 12 項自檢單打出來**」（強制走協議 3） |

**這三句話就是你的保險**（記住就夠，不必每次說）：

1. 「你沒輸出流程狀態」
2. 「先出任務規則表」
3. 「把 12 項自檢單打出來」

> 正常情況下協議會自動生效，這三句是兜底。但 AI 是機率性的 —— **你手上有這三句，它就沒有跑偏的空間。**

**想要更硬的話**（可選）：在支持 hook 的平台（WorkBuddy／Claude Code）可以加裝一個 Stop 鉤子，AI 想結束回答時自動檢查自檢單，沒輸出就攔住。配置方法見 `AGENTS.md` §九 —— **但這是選配，不影響跨平台使用。**

## 一點八、卡死了怎麼辦（重要）

**校驗是為了讓交付更好，不是為了讓交付不出來。** 如果它卡住不動了，按症狀處理：

| 症狀 | 你怎麼說 |
|---|---|
| 反覆改同一處、來回好幾輪 | 「**卡在哪了？把錯誤原文貼出來**」→ 它必須把問題攤開，並給你 2–3 個選項選 |
| 跑腳本報錯、環境不對（沒裝套件等） | 「**降級：不用腳本，直接出 Markdown**」→ 它應該繼續產出，並註明哪部分未經校驗 |
| 校驗過不了但你不想再等 | 「**跳過這項，先出稿**」→ 允許用緊急出口出稿，但**必須標明哪幾項沒過校驗** |
| 完全沒反應（對話太長／工具超時） | 開個新對話，說「繼續上一個營銷方案，上次停在 X」 |

**它的三條紅線**（你可以據此要求它）：

1. 同一個錯誤**不許重試超過 2 次**
2. **不許因為校驗不過就不交付**（卡住必須上報，不能自己死磕）
3. **不許靜默跳過校驗**（跳過必須告訴你跳了哪幾項）

> 一句話：**卡住就讓它上報，別讓它自己死磕。**

> 想跳過？只有明說「先按假設出一版」才行 —— 這時文檔首頁會標註「本方案基於未經驗證的假設」並列出假設清單。

## 二、怎麼觸發

已裝到 平台的 skills／插件目錄，任何會話直接說人話就會觸發：

> 「客戶是武漢光谷的川菜館，一家店，人均 60，月流水 25 萬，隔壁新開兩家同行，客流掉了三成，預算 3 萬，老闆自己幹。給我出方案。」

**信息給全了 → 直接進流程；給不全 → 它會問你。**

## 三、它會交付什麼

**一份 Word 文檔（`.docx`）**，簡體中文，八篇 + 附件。
> ⛔ 出稿走唯一入口：`python scripts/run_pipeline.py --rules rules.json --plan plan.md -o 方案.docx --title "…"`
> 它會依序跑門禁／預算／自檢／診斷，**任何一關不過就拿不到 `.docx`** —— 想跳過也跳不過。


| 篇 | 內容 |
|---|---|
| 執行摘要 | 1 頁：做什麼、花多少、預期什麼結果（結論先行） |
| 一 · 現狀分析 | 生意現狀（數據事實）／問題診斷（**A–H 問題類型**＋卡點重構句＋**核心動作一句**）／已排除的假設／約束與風險底線 |
| 二 · 策略 | **打法組合表（8 列，必寫）**／方案成立前提（三次收窄）／對手的結構性軟肋／節奏排期／產品與貨盤／特別專案 |
| 三 · 定位與口徑 | 定位與差異化支點／**禁用詞與紅線**／對不同人說什麼（各一套口徑）／命名 |
| 四 · 觸達與渠道 | 渠道選擇／路徑設計／內容與投放節奏／硬風險 |
| 五 · 落地文案與物料 | 物料清單（放哪、寫什麼、多少錢）／一線話術／待核實事實 |
| 六 · KPI 與追蹤 | 追蹤工具（土辦法也要能落地）／每日只看哪幾個數／決策節奏 |
| 七 · 預算明細 | 分項 + 合計（**能對上**）／盈虧線測算／追投與止損規則 |
| 八 · 執行與風控 | 行動清單／**執行人力檢查**／風險與關鍵假設／待解決問題／不做什麼 |
| 附件 | 物料文案全文／話術表／事實底稿／參考案例 |

**篇幅**：以《任務規則表》確認的**目標字數**為準（未指定時預設 **5,000–10,000 字**）。深度看「硬要素齊不齊」（五要素行動、禁用詞口徑、預算能對上、KPI、人力檢查、假設驗證），**不靠字數注水，也不為省字砍內容**。

## 四、它內部怎麼工作（六步）

```
第 0 步 門禁 ──── 13 項問清，沒問清不出方案
第 1 步 事實底稿 ── 把客戶告知的一切整理成唯一輸入源
第 2 步 現狀分析 ── 體檢（數據事實 + 我的判斷 + 已排除的假設）
第 3 步 多 Agent 分工 ── 策略 / 品牌 / 觸達 / 文案 / 財務風控，各寫各的
第 4 步 主理人裁決 ── 衝突裁決 + 合併成稿 + 跑自檢
第 5 步 交付 Word ── 生成 .docx
```

**多 Agent 分工（每次都走）**：
各 Agent **只讀事實底稿、不互讀草稿**（避免互相遷就、越寫越像）；衝突由主理人裁決並記錄理由。

## 六、交付前它會自己檢查（四類）

- **數字**：預算分項加總對不對？盈虧線算得對不對？【未核實】數據剔除了嗎？
- **執行**：每條動作有「誰做」嗎？負責人的工作量加起來做得完嗎？人力不夠時刪減順序寫了嗎？
- **風險**：對照失敗歸因過了一遍嗎？關鍵假設有驗證方式嗎？合規紅線過了嗎？與客戶約束衝突嗎？
- **表達**：有沒有「做私域」「加強內容」這類沒動作的廢話？結論前置了嗎？

項目結束後說一句：**「把這次學到的合併進 skill」**

| 你拿到的東西 | 合併到 |
|---|---|
| 新打法 | `references/00-打法库.md` |
| 新案例 | `references/cases/{行業}.md` |
| 新失敗 | `references/04-失败归因总库.md` |
| 新的好問法 | `SKILL.md` §五 |
| 新模型 | `references/03-方法论操作手册.md` |

**紅線**：不寫公司背景、不寫未核實數據、不寫客戶隱私。

## 七點五、語言紀律（公開倉庫必讀）

- **交付物一律簡體中文**（客戶看的）—— 這是硬要求，`build_docx.py` 出稿前會檢查。
- **skill 內部文檔一律繁體**（維護者看的）：SKILL／AGENTS／README／`references/00–08`／`cases/`。
- **唯一例外**：`references/范例/` 裡的**交付稿樣張是簡體**——因為它們就是交付物本身。

## 八、兩條使用紀律

1. **數據三級標註**：【已核實】／【行業認知】／【未核實】。**【未核實】不能寫進給客戶的交付物。**
2. **門禁不是形式** —— 你答得越細，方案越能用。含糊其辭只會得到一份正確但沒用的方案。
