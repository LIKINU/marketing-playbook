# 接案操作流程 SOP

> **这是什么**：操作流程 SOP：**S0–S8 逐步**——每步的输入／命令／产出／校验
> **什么时候读**：**一接案就跑**（不确定下一步做什么时，也读它）
> **读完你能**：当前处在第几步、下一步该跑哪条命令、产出应该长什么样
> **目录**：一、流程总览（9 阶段 · 每一步都有命令与校验） ｜ 二、逐阶段操作 ｜ 三、三档交付对照 ｜ 四、异常与降级（协议 8：卡死处理） ｜ 五、为什么这样设计（回应「模型做不到强制使用」） ｜ 六、维护注意（改哪里）
> **规模**：0.6 万字
> 定位：这份是**「怎么用这个 skill 干活」**的逐步操作手册。每一步写清：
> **何时做 / 输入 / 动作 / 命令 / 产出 / 校验 / 不过怎么办**。
> ⛔ **铁律**（用户 2026-09-16）：**规则写在代码里，不写在文字里**（模型不会看文字）；
> **知识由脚本机械注入**，不靠模型自愿引用（`composer.py`）。
> 🧭 配套工具：`scripts/flow.py`（流程向导，告诉你「现在第几步、下一步跑什么」）。
> `python scripts/flow.py --dir 案子目录` 看状态；加 `--check` 会顺带跑一次 `selfcheck` 并回传退出码。
>
> **产物命名约定**（`flow.py` 靠它们判断阶段）：`rules.json`（门禁）→ `skeleton.md`（composer 骨架）
> → `plan.md`（填空后）→ `方案.docx`（出稿）。放在同一个案子目录。

## 一、流程总览（9 阶段 · 每一步都有命令与校验）

```
S0 启动盘点 ─▶ S1 门禁13项 ─▶ S2 事实收集 ─▶ S3 组装骨架 ─▶ S4 填空在地化
              ─▶ S5 交付自检 ─▶ S6 深度诊断 ─▶ S7 出稿 ─▶ S8 交付与沉淀
```

| 阶段 | 谁做 | 一句话命令 | 产出 | 过不了会怎样 |
|---|---|---|---|---|
| S0 启动盘点 | 人/AI | `python scripts/flow.py` | 现状盘点 | 能力不足 → 按 AGENTS §四 降级 |
| S1 门禁 | 人/AI | `python scripts/gate_check.py rules.json` | 《任务规则表》 | 缺项 → **禁止产出方案内容** |
| S2 事实收集 | AI | （连接器/文件；先盘点工具） | 事实底稿 | 缺数据 → 标【未核实】、不得进交付物 |
| S3 组装骨架 | **脚本** | `python scripts/composer.py --rules rules.json --out skeleton.md --tier … --internal skeleton.internal.md` | `skeleton.md`（打法/理论/案例**已注入**）＋ `skeleton.internal.md`（施工说明，**不进交付稿**） | 解析失败 → 退出码 2 |
| **S3.5 多 Agent 分工** | **人/AI 协作** | 五角色（策略／品牌／触达／文案／财务风控）各写各的、互不看草稿 → 填 `roles.json` | `roles.json` | `role_check.py` 不过 → **不出稿** |
| S4 填空在地化 | **模型** | （只补 `【填】`；确认全文简体） | `plan.md` | 残留 `【填】` 或**繁体** → S5 判硬错误 |
| S5 交付自检 | **脚本** | `python scripts/selfcheck.py plan.md` | 自检报告 | 任一硬错误 → 退出码 1，**不得交付** |
| S6 深度诊断 | 脚本 | `python scripts/depth_check.py plan.md` | 9 维度报告 | **只诊断、不阻拦** |
| S7 出稿 | **脚本** | `python scripts/run_pipeline.py …` | `方案.docx` | 任一关不过 → 不生成 `.docx` |
| S8 交付与沉淀 | 人/AI | （见下） | 交付回复＋知识库沉淀 | — |

> **「谁做」是关键**：S3/S5/S7 是**脚本**（确定性、绕不过）；S4 是**模型唯一的活**；S1/S2/S8 是人与 AI 协作。

## 二、逐阶段操作

### S0 · 启动盘点（动笔前）
- **何时**：接到案子的第一件事
- **动作**：
  1. 读 `SKILL.md`（唯一入口）→ `AGENTS.md`（跨工具接入）→ 本 S O P
  2. **工具盘点先于路径**：先看已连接的连接器／MCP／API，**能直读就不硬爬**（AGENTS 协议 4）
  3. 跑 `python scripts/flow.py` 看目前卡在哪一步
- **产出**：现状一句话（材料在哪、缺什么）
- **校验**：确认「用得到的能力」都盘过；缺能力按 `AGENTS.md` §四 对照表**降级，不跳步**

### S1 · 门禁（13 项一次问全）→《任务规则表》
- **何时**：盘点后、动笔前
- **动作**：按 `SKILL.md §0` **门禁 13 项一次问全**（含**目标字数**）；用户每次纠偏＝规则表升级
- **命令**：`python scripts/gate_check.py rules.json`
- **产出**：`rules.json`（`client` ＋ `gate` 15 栏 ＋ `delivery`，末行 `rules_table_confirmed: true`）
- **校验**：退出码 0；且**规则表已请用户确认**
- **不过怎么办**：缺项 → **禁止产出任何方案内容**（协议 1）；用户说「先按假设出一版」→ 例外，但要在稿首标明假设

### S2 · 事实收集
- **何时**：门禁放行后
- **动作**：收客户数据／竞品／渠道事实；**先工具后爬虫**
- **产出**：事实底稿（内部文档，**不入交付稿**；交付稿只能在附件 C 引用）
- **校验**：每条数字标可信度（`【已核实】/【行业认知】/【未核实】`）；**`【未核实】` 不得进交付物**

### S3 · 组装骨架（本 skill 的核心 · 知识在这里被强制注入）
- **何时**：事实够了（不必等全部齐）
- **输入**：`rules.json`
- **命令**：
  ```bash
  python scripts/composer.py --rules rules.json --out skeleton.md --tier 标准 --top 5 \
      --internal skeleton.internal.md
  #  --tier  速览 | 标准 | G端        --top  打法条数（3–7）
  ```
- **脚本做什么（确定性，非模型生成）**：
  1. 解析 `00-打法库` 全部 §X.Y 打法（含「什么情况用／怎么做／怎么验收／案例」）
  2. 按 `SKILL.md §二 状况→打法 路由表`（编码在 `scripts/knowledge_map.json`）匹配状况 → 选 3–7 条打法
  3. 自动拉取每条打法的**具体动作 → 拆成编号步骤**（动作／时间／谁做／物料·话术／产出）＋验收指标＋可抄案例
  4. **注入「理论依据」**：打法 → `knowledge_map.json` → `03` 模型码 ＋ `49` 书籍
  5. 按档位输出骨架
- **产出**：`skeleton.md`（知识**已注入**；其余 `【填】` 待补）
- **校验**：composer 输出**天然过 `selfcheck` 第【7】【8】关**（可立即跑一遍确认）

### S4 · 填空与在地化（**模型唯一的活**）
- **何时**：骨架出来后
- **输入**：`skeleton.md`
- **动作（只做三件）**：
  1. 补 `【填】` 处：**卡点重构句**（「不是 X——是 Y」）／**KPI 目标数字**／**预算明细**（分项加总＝合计）／**风险四件套**（为什么会发生／预警信号／兜底预案／预防动作）／**自检单** 逐项 ✅
     ⛔ 补写时**不得**加入 `§X.X`／`（03 §C1）`／`cases/xx.md`／`模式 NN` 等内部坐标（selfcheck 第【10】关会拦）
  2. **确认全文是简体**（知识库已全仓统一简体，正常不会出繁体；出现繁体多半是**外部粘贴**进来的，逐字对照禁用词表＋`selfcheck` 第【9】关会拦）
  3. ⛔ **不得删改注入的打法／理论依据／可抄案例** —— 那是 skill 的强制输出
- **产出**：`plan.md`
- **校验**：`grep -c "【填】" plan.md` ＝ **0**

### S5 · 交付前自检
- **命令**：`python scripts/selfcheck.py plan.md`
- **产出**：八类检查报告（结构／自检单／内部文档／可信度／五要素／禁用词／核心方法论／**知识库引用**）
- **校验**：**退出码 0**（任何 ❌ 硬错误＝不得交付）
- **不过怎么办**：修正硬错误后重跑；**同一项连续 2 次不过 → 停止重试，摊给用户**（协议 8）

### S6 · 深度诊断（只诊断，不阻拦）
- **命令**：`python scripts/depth_check.py plan.md`
- **产出**：9 维度报告（竞品／风险四件套／KPI 预警线／物料／禁用词／重复度／空话词…）
- **校验**：无（**改不改由你决定**）

### S7 · 出稿（唯一出口）
- **命令**：
  ```bash
  python scripts/run_pipeline.py --rules rules.json --budget budget.json \
      --plan plan.md -o 方案.docx --title "客户名 营销方案" --date 2026-09-16
  ```
- **产出**：`.docx`（封面＋目录＋正文＋页码）
- **校验**：**拿不到 `.docx` ＝ 没完成**（它必跑 S1/S5，不过就拒绝生成）

### S8 · 交付与沉淀
- **动作**：
  1. 交付回复中**原样输出 12 项《交付自检单》**（协议 3）
  2. 剔除内部备注（底价／对人判断／内部策略）——对外交付物自动过滤
  3. 结案 3 天内写**复盘** → 规律回 B 层、套路回 skill `references/`
- **产出**：交付回复 + 复盘笔记
- **校验**：自检单 12 项全 ✅；无 `【未核实】` 进交付物

## 三、三档交付对照

| 档位 | 对象 | 产出重点 | composer 参数 |
|---|---|---|---|
| **速览** | 小微企业／个案 | 一页看懂打法：卡点＋3–7 条打法（逐步骤）＋预算量级 | `--tier 速览` |
| **标准** | B端客户 | 完整八篇方案（诊断／策略／定位／触达／文案／KPI／预算／风控） | `--tier 标准` |
| **G端** | 政府／公共项目 | 标准版 **＋** 政策依据与项目背景 ＋ 汇报稿/评审口径 ＋ 合规与舆情红线 ＋ 公文格式规范 | `--tier G端` |

## 四、异常与降级（协议 8：卡死处理）

| 情况 | 处理 |
|---|---|
| 同一项校验连续 2 次不过 | **停止重试**，把问题摊给用户 + 给 2–3 个选项（人来拍板） |
| 脚本报错／环境不可用 | **降级 Markdown 继续产出**（人工比对 §六 清单 + 输出 12 项自检单），不卡死 |
| 用户说跳过 | 允许（`build_docx.py --force`），但**必须声明未校验 + 列出未通过项** |
| 平台没有代码能力 | 退回 Markdown 协议（手工对照 + 样式对照说明）。**降级不等于跳步** |

## 五、为什么这样设计（回应「模型做不到强制使用」）

> **旧做法**：模型读 `03`/`00`/`cases`，自愿引用 → 相当于 prompt / RAG，模型可以整篇不引用。
> **新做法**：`composer.py` **机械把知识选出来、注入进骨架** → 模型拿到手的骨架里「打法＋模型＋学者＋案例」**已经在了，删不掉**。
> **兜底**：`selfcheck` 第【8】关再校验一遍（不过＝不出稿）。规则可以假装读过，**退出码假装不了**。

## 六、维护注意（改哪里）

| 要改什么 | 改哪个文件 |
|---|---|
| 「哪种状况用哪条打法」 | `scripts/knowledge_map.json` 的 `路由规则` |
| 「打法 → 理论依据」 | `scripts/knowledge_map.json` 的 `major_theory` / `play_overrides` |
| 档位结构／G端规范产物 | `scripts/composer.py` 的 `build_skeleton` |
| 自检门槛 | `scripts/selfcheck.py` |
| 门禁答案质量（过短／笼统） | `scripts/gate_check.py` 的 `MIN_LEN` |
| 多 Agent 分工校验 | `scripts/role_check.py` |
| 案例库体检（禁公司背景） | `python scripts/case_lint.py`（`--max` 设上限） |
| 案例库清理 | `python scripts/case_clean.py --apply --scope identity`（先 `--dry-run` 看；finance 范围会毁句，预设不动） |
| **改完任何脚本 → 回归验证** | `python scripts/smoke_test.py`（一条命令跑 12 项：该过的过、该拦的拦） |

**改完必做双向验证**：① 标杆范文 `selfcheck` 过（exit 0）② 造一份违规稿 `selfcheck` 拦（exit 1）。
