# 接案操作流程 SOP

> **這是什麼**：操作流程 SOP：**S0–S8 逐步**——每步的輸入／命令／產出／校驗
> **什麼時候讀**：**一接案就跑**（不確定下一步做什麼時，也讀它）
> **讀完你能**：當前處在第幾步、下一步該跑哪條命令、產出應該長什麼樣
> **目錄**：一、流程總覽（9 階段 · 每一步都有命令與校驗） ｜ 二、逐階段操作 ｜ 三、三檔交付對照 ｜ 四、異常與降級（協議 8：卡死處理） ｜ 五、為什麼這樣設計（回應「模型做不到強制使用」） ｜ 六、維護注意（改哪裡）
> **規模**：0.6 萬字
> 定位：這份是**「怎麼用這個 skill 幹活」**的逐步操作手冊。每一步寫清：
> **何時做 / 輸入 / 動作 / 命令 / 產出 / 校驗 / 不過怎麼辦**。
> ⛔ **鐵律**（用戶 2026-09-16）：**規則寫在代碼裡，不寫在文字裡**（模型不會看文字）；
> **知識由腳本機械注入**，不靠模型自願引用（`composer.py`）。
> 🧭 配套工具：`scripts/flow.py`（流程嚮導，告訴你「現在第幾步、下一步跑什麼」）。
> `python scripts/flow.py --dir 案子目錄` 看狀態；加 `--check` 會順帶跑一次 `selfcheck` 並回傳退出碼。
>
> **產物命名約定**（`flow.py` 靠它們判斷階段）：`rules.json`（門禁）→ `skeleton.md`（composer 骨架）
> → `plan.md`（填空後）→ `方案.docx`（出稿）。放在同一個案子目錄。

## 一、流程總覽（9 階段 · 每一步都有命令與校驗）

```
S0 啟動盤點 ─▶ S1 門禁13項 ─▶ S2 事實收集 ─▶ S3 組裝骨架 ─▶ S4 填空在地化
              ─▶ S5 交付自檢 ─▶ S6 深度診斷 ─▶ S7 出稿 ─▶ S8 交付與沉澱
```

| 階段 | 誰做 | 一句話命令 | 產出 | 過不了會怎樣 |
|---|---|---|---|---|
| S0 啟動盤點 | 人/AI | `python scripts/flow.py` | 現狀盤點 | 能力不足 → 按 AGENTS §四 降級 |
| S1 門禁 | 人/AI | `python scripts/gate_check.py rules.json` | 《任務規則表》 | 缺項 → **禁止產出方案內容** |
| S2 事實收集 | AI | （連接器/文件；先盤點工具） | 事實底稿 | 缺數據 → 標【未核實】、不得進交付物 |
| S3 組裝骨架 | **腳本** | `python scripts/composer.py --rules rules.json --out skeleton.md --tier …` | `skeleton.md`（打法/模型/學者/案例**已注入**） | 解析失敗 → 退出碼 2 |
| **S3.5 多 Agent 分工** | **人/AI 協作** | 五角色（策略／品牌／觸達／文案／財務風控）各寫各的、互不看草稿 → 填 `roles.json` | `roles.json` | `role_check.py` 不過 → **不出稿** |
| S4 填空在地化 | **模型** | （只補 `【填】`；繁體→簡體） | `plan.md` | 殘留 `【填】` 或**繁體** → S5 判硬錯誤 |
| S5 交付自檢 | **腳本** | `python scripts/selfcheck.py plan.md` | 自檢報告 | 任一硬錯誤 → 退出碼 1，**不得交付** |
| S6 深度診斷 | 腳本 | `python scripts/depth_check.py plan.md` | 9 維度報告 | **只診斷、不阻攔** |
| S7 出稿 | **腳本** | `python scripts/run_pipeline.py …` | `方案.docx` | 任一關不過 → 不生成 `.docx` |
| S8 交付與沉澱 | 人/AI | （見下） | 交付回覆＋知識庫沉澱 | — |

> **「誰做」是關鍵**：S3/S5/S7 是**腳本**（確定性、繞不過）；S4 是**模型唯一的活**；S1/S2/S8 是人與 AI 協作。

## 二、逐階段操作

### S0 · 啟動盤點（動筆前）
- **何時**：接到案子的第一件事
- **動作**：
  1. 讀 `SKILL.md`（唯一入口）→ `AGENTS.md`（跨工具接入）→ 本 S O P
  2. **工具盤點先於路徑**：先看已連接的連接器／MCP／API，**能直讀就不硬爬**（AGENTS 協議 4）
  3. 跑 `python scripts/flow.py` 看目前卡在哪一步
- **產出**：現狀一句話（材料在哪、缺什麼）
- **校驗**：確認「用得到的能力」都盤過；缺能力按 `AGENTS.md` §四 對照表**降級，不跳步**

### S1 · 門禁（13 項一次問全）→《任務規則表》
- **何時**：盤點後、動筆前
- **動作**：按 `SKILL.md §0` **門禁 13 項一次問全**（含**目標字數**）；用戶每次糾偏＝規則表升級
- **命令**：`python scripts/gate_check.py rules.json`
- **產出**：`rules.json`（`client` ＋ `gate` 15 欄 ＋ `delivery`，末行 `rules_table_confirmed: true`）
- **校驗**：退出碼 0；且**規則表已請用戶確認**
- **不過怎麼辦**：缺項 → **禁止產出任何方案內容**（協議 1）；用戶說「先按假設出一版」→ 例外，但要在稿首標明假設

### S2 · 事實收集
- **何時**：門禁放行後
- **動作**：收客戶數據／競品／渠道事實；**先工具後爬蟲**
- **產出**：事實底稿（內部文檔，**不入交付稿**；交付稿只能在附件 C 引用）
- **校驗**：每條數字標可信度（`【已核實】/【行業認知】/【未核實】`）；**`【未核實】` 不得進交付物**

### S3 · 組裝骨架（本 skill 的核心 · 知識在這裡被強制注入）
- **何時**：事實夠了（不必等全部齊）
- **輸入**：`rules.json`
- **命令**：
  ```bash
  python scripts/composer.py --rules rules.json --out skeleton.md --tier 标准 --top 5
  #  --tier  速览 | 标准 | G端        --top  打法條數（3–7）
  ```
- **腳本做什麼（確定性，非模型生成）**：
  1. 解析 `00-打法库` 全部 §X.Y 打法（含「什麼情況用／怎麼做／怎麼驗收／案例」）
  2. 按 `SKILL.md §二 狀況→打法 路由表`（編碼在 `scripts/knowledge_map.json`）匹配狀況 → 選 3–7 條打法
  3. 自動拉取每條打法的**具體動作 → 拆成編號步驟**（動作／時間／誰做／物料·話術／產出）＋驗收指標＋可抄案例
  4. **注入「理論依據」**：打法 → `knowledge_map.json` → `03` 模型碼 ＋ `49` 書籍
  5. 按檔位輸出骨架
- **產出**：`skeleton.md`（知識**已注入**；其餘 `【填】` 待補）
- **校驗**：composer 輸出**天然過 `selfcheck` 第【7】【8】關**（可立即跑一遍確認）

### S4 · 填空與在地化（**模型唯一的活**）
- **何時**：骨架出來後
- **輸入**：`skeleton.md`
- **動作（只做三件）**：
  1. 補 `【填】` 處：**卡點重構句**（「不是 X——是 Y」）／**KPI 目標數字**／**預算明細**（分項加總＝合計）／**風險四件套**（每條掛「模式 NN」）／**自檢單** 逐項 ✅
  2. 把注入的**繁體原文本地化為簡體**，逐字對照禁用詞表
  3. ⛔ **不得刪改注入的打法／理論依據／可抄案例** —— 那是 skill 的強制輸出
- **產出**：`plan.md`
- **校驗**：`grep -c "【填】" plan.md` ＝ **0**

### S5 · 交付前自檢
- **命令**：`python scripts/selfcheck.py plan.md`
- **產出**：八類檢查報告（結構／自檢單／內部文檔／可信度／五要素／禁用詞／核心方法論／**知識庫引用**）
- **校驗**：**退出碼 0**（任何 ❌ 硬錯誤＝不得交付）
- **不過怎麼辦**：修正硬錯誤後重跑；**同一項連續 2 次不過 → 停止重試，攤給用戶**（協議 8）

### S6 · 深度診斷（只診斷，不阻攔）
- **命令**：`python scripts/depth_check.py plan.md`
- **產出**：9 維度報告（競品／風險四件套／KPI 預警線／物料／禁用詞／重複度／空話詞…）
- **校驗**：無（**改不改由你決定**）

### S7 · 出稿（唯一出口）
- **命令**：
  ```bash
  python scripts/run_pipeline.py --rules rules.json --budget budget.json \
      --plan plan.md -o 方案.docx --title "客戶名 營銷方案" --date 2026-09-16
  ```
- **產出**：`.docx`（封面＋目錄＋正文＋頁碼）
- **校驗**：**拿不到 `.docx` ＝ 沒完成**（它必跑 S1/S5，不過就拒絕生成）

### S8 · 交付與沉澱
- **動作**：
  1. 交付回覆中**原樣輸出 12 項《交付自檢單》**（協議 3）
  2. 剔除內部備註（底價／對人判斷／內部策略）——對外交付物自動過濾
  3. 結案 3 天內寫**復盤** → 規律回 B 層、套路回 skill `references/`
- **產出**：交付回覆 + 復盤筆記
- **校驗**：自檢單 12 項全 ✅；無 `【未核實】` 進交付物

## 三、三檔交付對照

| 檔位 | 對象 | 產出重點 | composer 參數 |
|---|---|---|---|
| **速覽** | 小微企業／個案 | 一頁看懂打法：卡點＋3–7 條打法（逐步驟）＋預算量級 | `--tier 速览` |
| **標準** | B端客戶 | 完整八篇方案（診斷／策略／定位／觸達／文案／KPI／預算／風控） | `--tier 标准` |
| **G端** | 政府／公共項目 | 標準版 **＋** 政策依據與項目背景 ＋ 匯報稿/評審口徑 ＋ 合規與輿情紅線 ＋ 公文格式規範 | `--tier G端` |

## 四、異常與降級（協議 8：卡死處理）

| 情況 | 處理 |
|---|---|
| 同一項校驗連續 2 次不過 | **停止重試**，把問題攤給用戶 + 給 2–3 個選項（人來拍板） |
| 腳本報錯／環境不可用 | **降級 Markdown 繼續產出**（人工比對 §六 清單 + 輸出 12 項自檢單），不卡死 |
| 用戶說跳過 | 允許（`build_docx.py --force`），但**必須聲明未校驗 + 列出未通過項** |
| 平台沒有代碼能力 | 退回 Markdown 協議（手工對照 + 樣式對照說明）。**降級不等於跳步** |

## 五、為什麼這樣設計（回應「模型做不到強制使用」）

> **舊做法**：模型讀 `03`/`00`/`cases`，自願引用 → 相當於 prompt / RAG，模型可以整篇不引用。
> **新做法**：`composer.py` **機械把知識選出來、注入進骨架** → 模型拿到手的骨架裡「打法＋模型＋學者＋案例」**已經在了，刪不掉**。
> **兜底**：`selfcheck` 第【8】關再校驗一遍（不過＝不出稿）。規則可以假裝讀過，**退出碼假裝不了**。

## 六、維護注意（改哪裡）

| 要改什麼 | 改哪個檔 |
|---|---|
| 「哪種狀況用哪條打法」 | `scripts/knowledge_map.json` 的 `路由规则` |
| 「打法 → 理論依據」 | `scripts/knowledge_map.json` 的 `major_theory` / `play_overrides` |
| 檔位結構／G端規範產物 | `scripts/composer.py` 的 `build_skeleton` |
| 自檢門檻 | `scripts/selfcheck.py` |
| 門禁答案質量（過短／籠統） | `scripts/gate_check.py` 的 `MIN_LEN` |
| 多 Agent 分工校驗 | `scripts/role_check.py` |
| 案例庫體檢（禁公司背景） | `python scripts/case_lint.py`（`--max` 設上限） |
| 案例庫清理 | `python scripts/case_clean.py --apply --scope identity`（先 `--dry-run` 看；finance 範圍會毀句，預設不動） |
| **改完任何腳本 → 回歸驗證** | `python scripts/smoke_test.py`（一條命令跑 12 項：該過的過、該攔的攔） |

**改完必做雙向驗證**：① 標杆範文 `selfcheck` 過（exit 0）② 造一份違規稿 `selfcheck` 攔（exit 1）。
